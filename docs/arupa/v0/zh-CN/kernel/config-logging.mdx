---
title: "日志记录"
description: "配置结构化的内核和服务日志。"
---

Arupa 通过一个结构化的日志记录器写入内核和服务日志。默认输出格式为 JSON，因此可以按字段收集和搜索记录。您可以在终端中直接查看日志时切换到文本输出。

## 配置日志记录

在 `[Log]` 部分设置进程级日志记录选项：

```toml
[Log]
Format = "json"
Level = "info"
```

| 设置 | 值 | 描述 |
| --- | --- | --- |
| `Format` | `json`, `text` | 选择结构化的 JSON 记录，或人类可读的键值对文本。 |
| `Level` | `debug`, `info`, `warn`, `error` | 设置日志记录器发出的最低级别。 |

默认值为 `Format = "json"` 和 `Level = "info"`。级别过滤是包含性的：`warn` 会发出警告和错误，而 `debug` 会发出所有级别的日志。这些值不区分大小写。

配置加载时会报告配置错误。启动时，无效的日志记录设置会导致内核使用其默认值；重新加载期间，无效的配置会使当前配置保持生效。对 `[Log]` 的更改会在内核启动、创建日志记录器时生效；重新加载配置会更新诸如服务这类运行时设置，但不会替换已经在运行的日志记录器。

## 常用字段

每条内核日志都用两个字段标识其来源：

```text
component=kernel from=http
```

`component` 标识生成该记录的信任边界。`from` 标识内核子系统。常见的值包括：

- `http`，用于 HTTP 访问记录；
- `socketio`，用于 Socket.IO 连接和事件记录；
- `service_manager`，用于服务发现和生命周期记录；以及
- `config`、`server` 和 `cli`，分别用于配置、服务器和命令行活动。

服务通过已认证的主机边界发出的日志使用以下格式：

```text
component=service from=<service-name>
```

内核会从已认证的 gRPC 回调或 WASM 绑定上下文中推导出服务名称。服务无法通过提供不同的来源名称来更改这一归属。这适用于 `wasm` 和 `grpc` 服务；`static` 服务没有运行中的进程，因此永远不会发出自己的日志记录。服务协议本身没有变化，归属信息是由内核的主机日志层附加的。

## 调试源位置

当 `Level = "debug"` 时，日志记录器会自动为记录添加 `source` 字段，记录应用程序的调用位置。这有助于定位发出诊断记录的代码，但会增大每条记录的体积，通常也会增加日志量。

请勿将 `source` 与 `from` 混淆：

- `source` 是仅用于调试的日志记录器调用位置；而
- `from` 是稳定的内核子系统或服务标识。

在 `info`、`warn` 和 `error` 级别下，调用位置的 `source` 字段会被省略。

## HTTP 访问日志

内核会在每次 HTTP 请求后发出一条访问记录，包括由内核路由和服务路由处理的请求（无论该路由是被动态处理，还是通过静态传输提供打包文件），以及 Socket.IO 的 HTTP 端点。

每条记录包含：

| 字段 | 含义 |
| --- | --- |
| `method` | HTTP 方法。 |
| `path` | 请求路径，不含查询字符串。 |
| `status` | 最终的 HTTP 状态码。 |
| `duration_ms` | 请求耗时（毫秒）。 |
| `bytes_written` | 写入的响应体字节数。 |

访问记录使用 `component=kernel` 和 `from=http`。其日志级别根据最终状态选择：

- `4xx` 响应记录为 `WARN`；
- `5xx` 响应记录为 `ERROR`；以及
- 其余响应记录为 `INFO`。

请求体、请求头和查询字符串不会包含在此访问记录中。如果应用程序把敏感值放在路径片段中，路径本身仍可能包含敏感信息。

## Socket.IO 日志

Socket.IO 记录使用 `component=kernel` 和 `from=socketio`。内核会记录：

- 成功的连接和断开连接，级别为 `INFO`，包含命名空间和套接字 ID；
- 不可用的命名空间和被拒绝的连接，级别为 `WARN`；
- 格式错误或未声明的事件，级别为 `DEBUG`；
- 成功处理的事件，级别为 `DEBUG`，包含命名空间、事件名、服务名和 `duration_ms`；以及
- 当内核无法完成操作时，服务处理程序、负载处理或发送事件失败的记录，级别为 `ERROR`。

成功的事件日志永远不包含事件负载，错误记录同样会避免记录负载数据。当您需要有针对性的、经过脱敏的应用级诊断信息时，请使用服务自身的结构化日志。

## 选择日志级别

正常运行时使用 `info`。它包含 HTTP 访问记录、服务生命周期记录，以及 Socket.IO 的连接状态，但不会记录成功的 Socket.IO 事件。

当您需要排查被拒绝的请求、不可用的命名空间或其他可恢复的情况时，使用 `warn`。当您需要排查失败的请求或操作时，使用 `error`。

当您需要临时诊断路由选择结果、被忽略的 Socket.IO 事件、成功的事件处理过程，或某条日志记录的确切调用位置时，使用 `debug`。诊断完成后请恢复为 `info`，以减少日志量，避免收集超出必要程度的诊断细节。
